psgd.py — parallel SGD by iterative parameter mixing

A training superbatch of documents is handed out at random to K workers. Each worker starts from the same model, runs SGD on its share of the data, and the workers' parameters are then averaged at a central node and sent back out. The small colored strips are the model parameters (weights); the dots are documents.

One cycle

  1. start every worker from the same parameters
  2. randomly distribute the next superbatch
  3. each worker processes its τ minibatches
  4. workers send parameters to the central node
  5. the mean parameters are distributed back

Limiting cases

· K = 1 → exactly sgd.py.
· 1 superbatch → each worker trains its whole shard; average once at the very end.
· more superbatches → mix more often: closer to sequential SGD, more communication.
Parameters start at all zeros — logistic regression is convex, so every worker begins from the same point each cycle. Simulated time is what a real parallel run would cost: the workers run at once, so a cycle is max(worker compute) + averaging, not the sum. More workers shrink each worker's share of the data but add averaging noise — the tension the plot_psgd.py curves measure. Weights and loss here are an illustrative stand-in, not a real RCV1 run.

Multi-head, grouped-query, multi-query and latent attention

Each bar is one head's vector for a single token (bar height ∝ head dimension dh). Dashed lines show which key/value head each query head attends with. The variants differ in how many key/value heads they keep, which changes both the attention parameter count and the size of the KV cache needed at inference. Multi-head latent attention (MLA) instead caches one small latent vector per token and reconstructs every head's key and value from it. Click a panel to see the equations that define it.

Parameters per layer. Every variant has W_Q (dmodel × H·dh) and W_O (H·dh × dmodel). MHA, GQA and MQA have W_K and W_V of size dmodel × G·dh, with G = H, the chosen G, and 1 respectively; each caches 2·G·dh numbers per token per layer. MLA has a shared down-projection W_DKV (dmodel × dc) and per-head up-projections W_UK, W_UV (dc × H·dh), and caches only the dc-dimensional latent. At inference W_UK can be folded into W_Q and W_UV into W_O, so the full keys and values never need to be materialised.

Simplifications. Real DeepSeek-V2 MLA also compresses queries through a second latent (dc′ = 1536) and adds a small decoupled RoPE key (64 dims per token, also cached); both are omitted here, so the DeepSeek preset is approximate. KV-cache sizes assume 2 bytes per number (bf16). Figure layout after Ainslie et al., GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints (2023).

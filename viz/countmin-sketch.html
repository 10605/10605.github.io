The countmin sketch

A countmin sketch keeps t real vectors r1,…,rt of length m, one per hash function hi. Increment(x,v) adds v to ri[hi(x)] in every row; Retrieve(x) returns the minimum of those t cells. Collisions can only add to a cell, so the estimate is never too small — and it is wrong only if x collides in every row. Pseudo-code

Initialize(ε, δ):  m = ⌈e/ε⌉;  t = ⌈ln(1/δ)⌉  r1 = … = rt = 0mIncrement(x, v):  for i = 1, …, t:    ri[hi(x)] = ri[hi(x)] + vRetrieve(x):  return min(r1[h1(x)], …, rt[ht(x)])

Parameters & bounds

Cormode–Muthukrishnan: with m = ⌈e/ε⌉ and t = ⌈ln 1/δ⌉, Retrieve(x) ≥ a[x] always, and Retrieve(x) ≤ a[x] + ε‖a‖1 with probability ≥ 1 − δ.

Hash functions are seeded FNV-1a + a murmur-style mixer, reduced mod m; the stream is Zipf-distributed (a few characters are very common, most are rare), so heavy hitters are estimated well while rare names absorb most of the relative error. Changing m or t rebuilds the sketch from the calls processed so far.

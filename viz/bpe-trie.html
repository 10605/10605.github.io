Byte-pair encoding on a trie

Instead of keeping a token list for every word, store the corpus as a trie: each edge is a token, each root-to-leaf path is one word (ending in _), and each node records how many corpus words pass through it. Words that start the same way share a path, so their common prefix is stored, counted and merged only once. Nodes sit at a horizontal position equal to the number of characters consumed, so a merge removes the node between two edges and joins them into one longer edge. Edges the next merge will join are orange; edges created by the last merge are teal. Compare the same process on token lists.

Corpus trie

How a merge of (a, b) rewrites the trie

  1. Find sites: walk the trie from the root. A site is a node u whose incoming edge is a and that has a child v along edge b. (A trie node has at most one child per label, so there is at most one such v.)
  2. Re-parent: detach v from u and attach it to u's parent along a new edge ab. The subtree under v moves unchanged, and so do its counts.
  3. Prune: subtract count(v) from u. If u has no children left, delete it; otherwise it stays, still reached by a, for the words that continue differently.
  4. Recount: the count of pair (x, y) is the sum of count(w) over nodes w reached by edge y whose parent is reached by edge x. Only pairs touching a re-parented node change.

Walking top-down and continuing below the re-parented node merges each word left to right, so the trie always equals the prefix tree of the words' current token lists.

Ties between equally frequent pairs go to the alphabetically first pair, as on the token-list page, so both pages learn the same merges. In each node, the number is the count of corpus words through that node; at a leaf it is the word's frequency.

Putting the pieces together on one key vector x from a KV cache, with b bits per coordinate. TurboQuantmse rotates, quantizes every coordinate with the b-bit Lloyd–Max codebook, and rotates back. It minimizes ‖x − x̃‖2, but its inner products ⟨y, x̃⟩ are biased toward zero. TurboQuantprod spends b − 1 bits on TurboQuantmse and the last bit on QJL applied to the residual r = x − x̃mse, which makes ⟨y, x̃⟩ an unbiased estimate of ⟨y, x⟩ for every query y. The rotation Π and the Gaussian matrix S are drawn once and shared by all vectors.

300 random key/query pairs (keys with outlier channels, normalized to unit length; queries at random angles to them). Each dot is one pair, quantized with its own random Π and S: TurboQuant's guarantees are expectations over that randomness. (In a real cache one Π and S are shared, and across many different keys the errors average out the same way; our synthetic keys are all dominated by the same outlier channels, so with one shared draw they would mostly see the same luck, good or bad.)

Slope: least-squares fit of the estimate against the true ⟨y, x⟩ (1 = unbiased). Paper's upper bounds on E‖x − x̃‖² for TurboQuantmse: √3π/2 · 4−b ≈ 0.68, 0.17, 0.043, 0.011, with actual values ≈ 0.36, 0.117, 0.03, 0.009. For TurboQuantprod at b = 1 the whole budget goes to QJL.

The single example uses d ≤ 64 so each coordinate is visible; the guarantees improve as d grows (real heads use d = 64 to 128). QJL here uses m = d rows, so S is d×d. Norms are counted as 16-bit floats. The paper also handles outlier channels by giving them more bits (e.g. 2.5 or 3.5 bits on average); that refinement is not shown.

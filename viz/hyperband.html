Hyperband

Successive halving needs a choice of n, the number of configurations to start with: with a large n each one gets very little training before the first cut, so early learning curves can mislead and the best configuration may be dropped; with a small n, resources go to configurations that were never promising. Hyperband hedges by running successive halving several times, in brackets, all with about the same budget. Bracket s = smax starts many configurations with a tiny resource and cuts aggressively; bracket s = 0 is plain random search, training a few configurations with the full resource R. Hyperband returns the configuration with the lowest loss seen in any bracket. Here each configuration is a simulated learning curve: validation loss as a function of resource (e.g. epochs). See successive halving for the subroutine.

Late bloomers = 0: how fast a configuration learns is unrelated to how good it ends up, so early losses rank configurations well. Late bloomers = 1: the best configurations are also the slowest learners, so early losses are misleading.

Repeat many times

With fresh configurations each time, compare Hyperband with running a single bracket repeatedly with the same total budget. Lower is better.

Simulated configurations. Configuration c has learning curve Lc(r) = fc + ac·exp(−r/τc): it converges toward loss fc on time scale τc. Each evaluation adds Gaussian noise. The late-bloomer setting blends a random time scale with one that is longest for the configurations with the lowest fc. A configuration's quality is its loss after full training, Lc(R). As in the paper's analysis, each rung's evaluation is charged its full resource ri (no reuse of earlier training), so every bracket uses about B = (smax+1)R units.

Algorithm from Li, Jamieson, DeSalvo, Rostamizadeh and Talwalkar, Hyperband: A Novel Bandit-Based Approach to Hyperparameter Optimization, JMLR 18 (2018).

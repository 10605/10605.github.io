Key-value caching

A decoder generates autoregressively: each new token is appended to the input and the model runs again. Here one masked self-attention layer is shown, simplified to QK⊤V (no scaling or softmax). Because of the causal mask, row i of every matrix depends only on tokens 1..i, so everything in the green boxes is the same as in the previous step. The keys and values can be cached, and each step then only needs the newest token's query. Step through, then switch on the cache.

Cost of attention in this layer

Why only the query of the new token is needed. If xi is token i's representation entering the layer, then qi = xiWQ, ki = xiWK and vi = xiWV. The QK⊤ product is the only place where information moves from one token to another, and the mask means output row i uses only qi, k1..i and v1..i. Only the last output row is needed to predict the next token. So step t needs qt plus all keys and values up to t, and all of them except kt and vt were already computed at earlier steps.

Every layer. The same argument applies layer by layer. Row i of each layer's output depends only on tokens 1..i, so the xi fed to the next layer is also unchanged. Each layer (and each key/value head) keeps its own cache. Its size grows linearly with the context length, which is what multi-query, grouped-query and latent attention reduce (see attention-heads.html).

Counting. The table counts vector operations: a projection is one xiW product, a dot product is one qi·kj, and an output row is one weighted sum of value vectors. Only the unmasked entries of QK⊤ are counted; a dense implementation computes all t2 entries and then masks them. Figure layout after J. Lages, Transformers KV Caching Explained.
